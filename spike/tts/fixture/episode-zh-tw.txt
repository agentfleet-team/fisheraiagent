早安，歡迎收聽今天的晨間 podcast。現在是早上七點，我是你的 AI 主持人。今天我們用大約十分鐘，替你整理三支值得一看的影片，主題都跟你最近關心的方向有關：agent workflow 的設計、AI 的 memory 機制，還有企業導入 AI 的實務經驗。咖啡倒好了嗎？如果還沒有，也沒關係，先按下播放，一邊準備一邊聽。那我們開始吧。

先講第一個主題，agent workflow。這支影片的講者是一位長期做自動化的工程師，他提出一個很實用的觀點：不要一開始就追求全自動，而是先把流程拆成清楚的節點，每個節點只做一件事。他舉了一個客服的例子，第一個節點負責分類問題，第二個節點負責查詢知識庫，第三個節點才負責產生回覆。每個節點都有明確的輸入和輸出，這樣出錯的時候，你可以馬上知道問題卡在哪一步。

講者也提到，很多團隊失敗的原因，是把整個流程都交給一個很長的 prompt，結果模型一旦跑偏，就很難除錯。他的建議是用腳本掌握流程的順序，讓模型只在被指定的節點裡思考，而不是讓模型自己決定下一步要做什麼。這樣做的好處是，每一次執行都可以被記錄、被重播，成本也比較容易估算。他還特別強調，要替每個節點準備一組固定的測試案例，只要改了 prompt，就先跑一遍，確定舊的案例都還能通過，再往下走。

我自己覺得這一點對小團隊特別重要。人少的時候，你沒有時間每天盯著系統，所以流越單純、越可以重跑，你晚上就睡得越安穩。講者最後給了一個小提醒：每多加一個 agent，溝通成本就會上升，所以在新增角色之前，先問自己，這件事能不能用一個函式解決，答案常常是可以。

另外，講者在影片開頭提醒大家，工具會一直換，今天流行的框架，半年後可能就沒人討論了。真正可以累積的，是你對自己工作流程的理解。這個提醒我很喜歡，也很適合放在一週的開始。

他還分享了一個除錯的小技巧：每個節點執行完，都把輸入、輸出和耗時寫進同一份紀錄檔。隔天早上你只要打開那份檔案，就能看出昨晚哪一步變慢、哪一步重試了三次，不需要重新跑一遍才知道問題在哪裡。對一個每天固定時間要交出成果的系統來說，這種可以回頭檢查的習慣，比任何聰明的設計都更有價值。

接著進入第二個主題，memory。這支影片是一場技術分享，主題是為什麼大型語言模型看起來很聰明，卻常常忘記昨天發生的事。講者先釐清一個常見的誤解：模型本身並沒有記憶，所謂的 memory，其實是我們在每一次對話開始前，把一部分資料重新放進 context 裡面。換句話說，記憶是一個系統設計問題，不是模型的內建能力。

他把 memory 分成三層。第一層是短期記憶，也就是目前這段對話的內容，受限於 context window 的大小。第二層是工作記憶，通常是一份摘要或筆記，記錄這個任務目前做到哪裡、做了哪些決定。第三層是長期記憶，會把重要的事實存進資料庫，需要的時候再用檢索的方式撈回來。講者提醒，長期記憶最大的風險不是存不下，而是撈錯東西。如果檢索回來的內容過時，或是跟現在的問題無關，模型反而會被誤導，答案比沒有記憶還糟。

所以他建議，寫入記憶之前要先判斷值不值得存，並且為每一筆資料標上來源和日期。讀取的時候，也要讓模型知道這是一筆歷史資料，而不是現在的事實。這個觀念很簡單，但是做到的團隊不多。如果你正在替自己的 agent 設計記憶，不妨先從一份每天更新的摘要檔開始，等真的不夠用，再考慮加上向量資料庫。

講者還示範了一個具體的做法。他讓 agent 在每次任務結束時，只寫下三句話：這次做了什麼、遇到什麼限制、下一次要注意什麼。隔天開始工作前，系統只讀回最近幾天的這幾句話，而不是整段歷史對話。他說，這樣的成本很低，卻能讓 agent 的表現明顯穩定，因為模型每天看到的都是整理過、重點清楚的資料，而不是一大堆沒有排序的雜訊。

第二支影片的最後，講者回答了現場觀眾的一個問題：記憶要保存多久才合理？他的答案是，沒有固定的天數，要看資料的性質。像是使用者的偏好，可以保存很久；像是某一次的錯誤訊息，可能一個星期之後就沒有用了。所以他建議替每一類資料設定到期日，定期清理，讓記憶庫保持乾淨，檢索的結果也會比較準。

第三個主題，企業導入 AI 的實務經驗。這支影片是一位顧問分享他輔導十幾家公司的心得。他說，最常見的失敗模式不是技術不夠好，而是一開始就選了太大的題目，例如要全公司一起導入，結果每個部門的需求都不同，專案拖了半年還看不到成果。成功的公司通常反過來做，先挑一個每天都在發生、而且大家都覺得很煩的小工作，例如整理會議紀錄，或是回覆固定格式的詢價信，用兩到三週做出可以用的版本。

他也分享了一個衡量成效的方法。不要只看省了多少時間，而是看這個工具有沒有被同事主動使用。如果大家每天都開著它，就代表它真的解決了問題；如果只有專案負責人在用，那就算報表上的數字很漂亮，也很可能撐不了多久。另外，他建議每一家公司都指定一位內部的窗口，負責收集同事的回饋，因為最了解流程的人，永遠是每天做那件事的人，而不是外部的顧問。

顧問還補充了一個很實際的觀察：預算通常不是最大的阻礙，真正的阻礙是資料。許多公司的檔案散落在個人電腦、聊天群組和舊的共用資料夾裡，名稱也不一致。所以他會要求客戶在正式開發之前，先花一週整理最常用的二十份文件，並且指定誰負責更新。這個動作看起來很不起眼，卻往往決定了後面的成敗，因為模型再強，也無法回答一份找不到的文件。

最後他談到信任這件事。他說，員工對 AI 的態度，往往取決於主管怎麼定位它。如果主管說這是用來取代人的，大家就會抗拒；如果說這是用來接手最無聊的那一段，讓大家把時間花在判斷和溝通上，接受度就會高很多。這個說法，我覺得跟前面兩支影片其實是呼應的：好的系統，都是讓人和機器各自做擅長的事。

聽到這裡，你可能會問，這三件事要從哪裡開始做？我的建議是挑最小的一步：今天下班前，把你手上最常重複的一項工作寫成三到五個步驟，標出哪一步需要判斷、哪一步只是照做。這一份清單，就是你的第一個 workflow，也是你日後加入記憶和擴大導入的基礎。

好，今天的三個主題就到這裡。我們快速回顧一下：第一，把 agent workflow 拆成節點，用腳本掌握順序；第二，memory 是系統設計，寫入前先判斷，讀取時標明來源；第三，導入 AI 先從小而煩的工作開始，並且看同事有沒有主動使用。

如果你今天只想帶走一件事，我會選第一點：先讓流程可以重跑，再談聰明。謝謝你花十分鐘陪我，如果內容對你有幫助，歡迎把它分享給同樣在做 AI 的朋友，祝你有個順利又平靜的一天，我們明天早上同一時間再見，掰掰。
